# Container queries

[Breakpoints](../breakpoints) change a layout based on the viewport width. Container queries let a widget adapt to the width of an ancestor container instead, so two widgets can use different layouts at the same viewport width. Both helpers use the same breakpoint scale and unit, with inclusive lower and exclusive upper boundaries.

## Overview

This example uses two rules at the same time. Resize the browser to see what each rule controls:

- **Viewport:** `breakpoints.gte('md')` puts the sidebar and main area side by side at <Code>{formatBreakpoint(breakpoints, 'md')}</Code> (<Code>{formatBreakpoint(breakpoints, 'md', 'px')}</Code> with a `16px` initial font size). Below that, they stack.
- **Container:** `containerQueries.gte(14)` gives each gallery three columns when its own container reaches `14rem` (`224px` with a `16px` root font size). The sidebar stays at one column even when both galleries are side by side.

{render('./usage')}

Inside a `TonicProvider`, apply the breakpoint to the outer layout. Set `containerType: 'inline-size'` on each gallery container and apply the container query to the grid inside it.

```jsx
import { Box, useTheme } from '@tonic-ui/react';

function PhotoGrid({ width, children }) {
  const { containerQueries } = useTheme();

  return (
    <Box sx={{ width, maxWidth: '100%', containerType: 'inline-size' }}>
      <Box sx={{
        display: 'grid',
        gridTemplateColumns: '1fr',
        gap: '2x',
        [containerQueries.gte(14)]: { gridTemplateColumns: 'repeat(3, minmax(0, 1fr))' },
      }}>
        {children}
      </Box>
    </Box>
  );
}

function GalleryLayout({ photos }) {
  const { breakpoints } = useTheme();

  return (
    <Box sx={{
      display: 'flex',
      flexDirection: 'column',
      gap: '6x',
      [breakpoints.gte('md')]: { flexDirection: 'row' },
    }}>
      <PhotoGrid width="192px">{photos}</PhotoGrid>
      <PhotoGrid width="384px">{photos}</PhotoGrid>
    </Box>
  );
}
```

The helpers produce explicit nested keys for `sx` or `__sx`, not property-level breakpoint objects. You can still use a whole-`sx` or `__sx` composition array to combine objects containing container rules. Rules follow normal CSS cascade order; the helpers do not sort them.

If you use a `Box` theme callback instead of `useTheme()`, guard `theme.containerQueries` before calling it. A `Box` can also render without a provider.

## Named containers

An unnamed query measures the nearest ancestor that supports width queries. To measure a specific ancestor instead, set `containerName: 'gallery'` on that ancestor alongside `containerType: 'inline-size'`, and use `containerQueries('gallery').gte(14)` as an `sx` key on the descendant.

## Customizing container queries

Configure [breakpoints](../breakpoints) with `createTheme()` to change the shared widths or unit. There is no separate container query scale.

```jsx
import { createTheme } from '@tonic-ui/react';

const theme = createTheme({
  breakpoints: {
    values: { sm: 30, md: 50 },
    unit: 'rem',
  },
});

theme.containerQueries('sidebar').only('sm');
// '@container sidebar (30rem <= width < 50rem)'
```

For a style that applies on both sides of a range, use it as the base style and override it within the range with `only()` or `between()`. To match only outside a range, use native CSS directly as an `sx` key:

```jsx
<Box sx={{ '@container sidebar not (40rem <= width < 48rem)': { display: 'flex' } }} />
```

Raw `@container` rules do not require a helper.

## API

The callable `theme.containerQueries` exposes `gte`, `lt`, `between`, and `only` directly for unnamed queries, or on the object returned by `theme.containerQueries(name)` for named queries. With the default theme:

| Call | Result |
| :--- | :--- |
| `containerQueries.gte('sm')` | <Code>{containerQueries.gte('sm')}</Code> |
| `containerQueries.lt('md')` | <Code>{containerQueries.lt('md')}</Code> |
| `containerQueries.between('sm', 'lg')` | <Code>{containerQueries.between('sm', 'lg')}</Code> |
| `containerQueries.only('md')` | <Code>{containerQueries.only('md')}</Code> |
| `containerQueries('sidebar').gte(18.75)` | <Code>{containerQueries('sidebar').gte(18.75)}</Code> |

`gte`, `lt`, and `between` accept configured breakpoint names or numeric widths in the configured breakpoint unit. With the default `rem` unit, `18.75` means `18.75rem`, or `300px` when the root font size is `16px`. Raw length strings such as `'300px'` are not supported. `only` accepts a configured breakpoint name and ends before the next breakpoint, or has no upper bound for the last name. Unknown or unconfigured names throw. See [breakpoints](../breakpoints) for the available names and configuration.
