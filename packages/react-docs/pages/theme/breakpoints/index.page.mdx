# Breakpoints

Breakpoints define viewport widths for responsive styles and CSS media queries.

`createTheme()` uses `rem` by default. See the [breakpoint tokens](../design-tokens/breakpoints) for the default widths, or define [custom breakpoints](#custom-breakpoints) for your project.

## CSS media queries

Use CSS media queries to apply styles based on the viewport width. `theme.breakpoints` provides four helpers:

- [`theme.breakpoints.gte(start)`](#themebreakpointsgte)
- [`theme.breakpoints.lt(end)`](#themebreakpointslt)
- [`theme.breakpoints.between(start, end)`](#themebreakpointsbetween)
- [`theme.breakpoints.only(name)`](#themebreakpointsonly)

The demo uses breakpoints in pixels. Resize the browser to see which queries match. More than one can match at the same width.

{render('./media-queries')}

Read `breakpoints` with `useTheme()` inside a `TonicProvider`. Each helper returns a CSS media query that can be used as a key in `sx`.

<CodeBlock language="jsx" code={`import { Box, createTheme, TonicProvider, useTheme } from '@tonic-ui/react';

const theme = createTheme({
  breakpoints: {
    values: { ${pixelValuesCode} },
    unit: '${pixelBreakpoints.unit}',
  },
});

function ResponsiveBox() {
  const { breakpoints } = useTheme();

  return (
    <Box sx={{ backgroundColor: 'background.low', [breakpoints.only('md')]: { backgroundColor: 'background.high' } }} />
  );
}

function App() {
  return (
    <TonicProvider theme={theme}>
      <ResponsiveBox />
    </TonicProvider>
  );
}
`} />

To use the same style on both sides of a range, set it as the base style and override it inside the range with `only()` or `between()`, as in the example above. If a rule must match only outside a range, write a native CSS query directly, such as `@media not (768px <= width < 1024px)`.

Viewport breakpoints still apply when a widget sits in a narrow sidebar. To make a widget respond to its own container instead, continue with [Container queries](../container-queries).

Responsive style props accept breakpoint objects. In `sx`, use the helpers as media query keys.

## Custom breakpoints

Set `breakpoints` in `createTheme()` to customize the viewport widths used by responsive styles and media query helpers.

- `theme.breakpoints.values`: Defines the minimum width for each breakpoint. Tonic UI sorts breakpoints by width.
- `theme.breakpoints.unit`: Specifies the unit used for breakpoint values. The default scale uses `rem`, but custom values default to `px` when no unit is specified.

Setting `values` replaces the entire breakpoint scale. Include all breakpoints you want to keep.

The following examples show the default breakpoint values in `px` and their equivalents in `rem`:

```js
// px
const theme = createTheme({
  breakpoints: {
    values: {
      xs: 0,
      sm: 640,
      md: 768,
      lg: 1024,
      xl: 1280,
      '2xl': 1536,
    },
    unit: 'px',
  },
});

// rem
const theme = createTheme({
  breakpoints: {
    values: {
      xs: 0,
      sm: 40,
      md: 48,
      lg: 64,
      xl: 80,
      '2xl': 96,
    },
    unit: 'rem',
  },
});
```

You can also name breakpoints for your project's layouts. Custom names start with a letter and can contain letters, digits, and hyphens.

```js
import { createTheme } from '@tonic-ui/react';

const theme = createTheme({
  breakpoints: {
    values: {
      mobile: 0,
      tablet: 640,
      laptop: 1024,
      desktop: 1200,
    },
  },
});

theme.breakpoints.only('tablet'); // '@media (640px <= width < 1024px)'
theme.containerQueries('sidebar').gte('tablet'); // '@container sidebar (width >= 640px)'
```

Only the supplied names are available on this theme. You can also use them in responsive props, such as `width={{ _: '100%', tablet: '50%' }}`. `createTheme()` infers the names for its return value. Inside a component under this theme's provider, TypeScript callers can use `useTheme<(typeof theme.breakpoints.keys)[number]>()` to specify those names.

## Rule composition

These snippets use `breakpoints` from `useTheme()` with the pixel configuration in [CSS media queries](#css-media-queries). They show how matching rules combine or override individual properties.

### Set related styles in one rule

When width and text color change together, put both declarations in the same media query rule.

```jsx
<Box sx={{
  width: '100%',
  [breakpoints.gte('sm')]: {
    width: '50%',
    color: 'text.secondary',
  },
  [breakpoints.gte('md')]: {
    width: '100%',
    color: 'text.primary',
  },
}}>
  Orders
</Box>
```

**Resulting styles**

| Viewport width | Styles |
| :--- | :--- |
| **Below `sm`**<br /><span>{`< ${exampleSmPx}`}</span> | `color: inherit;`<br />`width: 100%;` |
| **From `sm` to below `md`**<br /><span>{`${exampleSmPx} to under ${exampleMdPx}`}</span> | `color: var(--tonic-colors-text-secondary);`<br />`width: 50%;` |
| **`md` and above**<br /><span>{`≥ ${exampleMdPx}`}</span> | `color: var(--tonic-colors-text-primary);`<br />`width: 100%;` |

At `md`, both queries match. The later rule wins for both properties.

### Compose rules for the same query

Use an `sx` array when the declarations come from separate style objects. Here, two objects use the same `gte('sm')` key: one sets color and the other sets width.

```jsx
<Box sx={[
  { width: '100%' },
  { [breakpoints.gte('sm')]: {
    color: 'text.secondary',
  } },
  { [breakpoints.gte('sm')]: {
    width: '50%',
  } },
  { [breakpoints.gte('md')]: {
    width: '100%',
    color: 'text.primary',
  } },
]}>
  Returns
</Box>
```

**Resulting styles**

| Viewport width | Styles |
| :--- | :--- |
| **Below `sm`**<br /><span>{`< ${exampleSmPx}`}</span> | `color: inherit;`<br />`width: 100%;` |
| **From `sm` to below `md`**<br /><span>{`${exampleSmPx} to under ${exampleMdPx}`}</span> | `color: var(--tonic-colors-text-secondary);`<br />`width: 50%;` |
| **`md` and above**<br /><span>{`≥ ${exampleMdPx}`}</span> | `color: var(--tonic-colors-text-primary);`<br />`width: 100%;` |

The two `gte('sm')` rules combine to produce the same result as the Orders example.

### Override width without changing color

Use `&&` to give just the width declaration higher selector specificity. Leave color in the media query rules.

```jsx
<Box sx={{
  [breakpoints.gte('sm')]: {
    color: 'text.secondary',
  },
  [breakpoints.gte('md')]: {
    width: '100%',
    color: 'text.primary',
  },
  '&&': { width: '50%' },
}}>
  Alerts
</Box>
```

**Resulting styles**

| Viewport width | Styles |
| :--- | :--- |
| **Below `sm`**<br /><span>{`< ${exampleSmPx}`}</span> | `color: inherit;`<br />`width: 50%;` |
| **From `sm` to below `md`**<br /><span>{`${exampleSmPx} to under ${exampleMdPx}`}</span> | `color: var(--tonic-colors-text-secondary);`<br />`width: 50%;` |
| **`md` and above**<br /><span>{`≥ ${exampleMdPx}`}</span> | `color: var(--tonic-colors-text-primary);`<br />`width: 50%;` |

At `md`, `&&` overrides `width: '100%'` without affecting text color.

## API

The read-only `theme.breakpoints` object exposes `keys`, `values`, `unit`, and the four helpers below. The examples use the pixel configuration from [CSS media queries](#css-media-queries).

A **boundary** is a configured breakpoint name, a non-negative decimal length string ending in `px`, `rem`, or `em`, or the number `0`. Names use the theme's value and unit. Explicit lengths keep their units. Unknown names, unitless strings, and CSS functions such as `calc()` are not accepted.

The default scale starts at `xs: 0`. Use `gte('xs')` for the configured `xs` threshold. Use `gte(0)` for a fixed zero bound, even if `xs` changes or is omitted.

<span id="themebreakpointsgte" />

### `theme.breakpoints.gte(start) => media query`

**Arguments**

1. `start` (boundary): The minimum viewport width.

**Returns**

A media query string that matches widths at or above `start`.

**Examples**

<CodeBlock language="js" code={`breakpoints.gte('sm');    // '${exampleBreakpoints.gte('sm')}'
breakpoints.gte('800px'); // '${exampleBreakpoints.gte('800px')}'
breakpoints.gte(0);       // '${exampleBreakpoints.gte(0)}'`} />

<span id="themebreakpointslt" />

### `theme.breakpoints.lt(end) => media query`

**Arguments**

1. `end` (boundary): The exclusive upper bound.

**Returns**

A media query string that matches widths below `end`.

**Examples**

<CodeBlock language="js" code={`breakpoints.lt('sm');    // '${exampleBreakpoints.lt('sm')}'
breakpoints.lt('800px'); // '${exampleBreakpoints.lt('800px')}'`} />

<span id="themebreakpointsbetween" />

### `theme.breakpoints.between(start, end) => media query`

**Arguments**

1. `start` (boundary): The inclusive lower bound.
2. `end` (boundary): The exclusive upper bound.

**Returns**

A media query string that matches widths at or above `start` and below `end`. The helper does not convert units.

**Examples**

<CodeBlock language="js" code={`breakpoints.between('sm', 'md');      // '${exampleBreakpoints.between('sm', 'md')}'
breakpoints.between('700px', '960px'); // '${exampleBreakpoints.between('700px', '960px')}'`} />

<span id="themebreakpointsonly" />

### `theme.breakpoints.only(name) => media query`

**Arguments**

1. `name` (string): A configured breakpoint name.

**Returns**

A media query string that matches widths from the named breakpoint up to, but not including, the next configured breakpoint. If there is no next breakpoint, the query has no upper bound.

**Examples**

<CodeBlock language="js" code={`breakpoints.only('sm');  // '${exampleBreakpoints.only('sm')}'
breakpoints.only('md');  // '${exampleBreakpoints.only('md')}'
breakpoints.only('2xl'); // '${exampleBreakpoints.only('2xl')}'`} />
