# Responsive values

Responsive values use the [breakpoints](../../theme/design-tokens/breakpoints) defined in the theme. Each breakpoint starts at its minimum viewport width.

| Breakpoint | Minimum width | At 16px |
| :--------- | :------------ | :------ |
| `sm` | `40rem` | `640px` |
| `md` | `48rem` | `768px` |
| `lg` | `64rem` | `1024px` |
| `xl` | `80rem` | `1280px` |
| `2xl` | `96rem` | `1536px` |

Pixel equivalents assume the browser's default initial font size of `16px`.

Use a breakpoint object on a flat style prop. Responsive value arrays are no longer supported in style props or in individual `sx` or `__sx` declarations.

## Breakpoint object syntax

Named keys make the intended breakpoints explicit. Use `_` for an unconditional base value:

```jsx
<Text fontSize={{ _: 24, md: 32, lg: 40, xl: 48 }}>
  This is a text
</Text>
```

The base font size is `24px`. At `md` (`≥ 48rem`) it becomes `32px`, at `lg` (`≥ 64rem`) it becomes `40px`, and at `xl` (`≥ 80rem`) it becomes `48px`. A value continues to apply until another matching breakpoint overrides it. Omit `_` if no base declaration is needed. Unconfigured breakpoint names are ignored.

## Responsive styles in `sx`

Keep breakpoint objects on flat style props. Inside `sx` or the internal `__sx` channel, use explicit media query keys instead. In a child of `TonicProvider`, use the active theme's helpers:

```jsx
import { Box, useTheme } from '@tonic-ui/react';

function ResponsiveBox() {
  const { breakpoints } = useTheme();

  return (
    <Box sx={{ width: '100%', [breakpoints.gte('md')]: { width: '50%' } }} />
  );
}
```

You can also use a native media query as a key. A breakpoint object inside an `sx` property is a nested rule, not a responsive value. See [breakpoint media queries](../../theme/breakpoints#css-media-queries) for more examples.

Arrays passed to `sx` itself, or to the internal `__sx` channel, still compose style objects in order. They are not responsive value arrays:

```jsx
<Box sx={[{ color: 'black' }, { '&:hover': { color: 'blue' } }]} />
```

## Migrating removed responsive arrays

Map each old array position using the breakpoint scale configured in the old theme, then use named keys for flat props or explicit media query keys in `sx`. For example, an earlier scale placed `xs` at `0px` after the unconditional base, so `xs` matched every nonnegative viewport and index `4` was `lg`:

```jsx
// Before: removed array syntax with the earlier xs-based scale.
<Text fontSize={['4xl', '3xl', null, null, 48]} />

// After: xs becomes the base, and the large size starts at lg.
<Text fontSize={{ _: '3xl', lg: 48 }} />
```

If the old `xs` slot was empty, retain the original base instead. Recheck the actual viewport thresholds: configured breakpoint widths may have changed along with their names or positions.

## Under the hood

Given the following example:

```jsx
<Box width={{ _: '100%', sm: '50%', md: '25%' }}>
  This is a box
</Box>
```

The responsive style props generate the following CSS:

```css
.Box {
  width: 100%;
}

@media (width >= 40rem) {
  .Box {
    width: 50%;
  }
}

@media (width >= 48rem) {
  .Box {
    width: 25%;
  }
}
```
