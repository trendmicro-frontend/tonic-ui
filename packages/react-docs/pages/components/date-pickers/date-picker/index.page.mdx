# DatePicker

`DatePicker` let the user select a date from the calendar.

## Import

```js
import {
  DatePicker,
} from '@tonic-ui/react';
```

## Overview

The following example demonstrates a simple example of the `DatePicker` component.

```jsx
<DatePicker
  closeOnSelect={true}
  inputFormat="yyyy-MM-dd"
  value={value}
  onChange={(nextValue) => {
    setValue(nextValue);
  }}
  onError={(error, value) => {
    console.log(error, value);
  }}
  renderInput={({ error, inputProps }) => (
    <DateInput
      {...inputProps}
      error={error}
      placeholder="yyyy-MM-dd"
      readOnly
    />
  )}
/>
```

Note that the `DateInput` component is currently not provided by the `@tonic-ui/react` package. You have to write your own or refer to the following code to [get started](../../input-control).

```jsx
// import
import { InputControl, InputAdornment } from '@tonic-ui/react';
import { CalendarIcon } from '@tonic-ui/react-icons';

// DateInput
const DateInput = React.forwardRef((props, ref) => {
  return (
    <InputControl
      ref={ref}
      startAdornment={(
        <InputAdornment color="text.secondary">
          <CalendarIcon />
        </InputAdornment>
      )}
      {...props}
    />
  );
});
```

### Date time range picker

Range selection is not a built-in `DatePicker` feature. This example composes two `DatePicker` inputs (start date and end date) with two time inputs inside a `Menu`, and manages the range as application state:

- **Draft state**: `DateTimePicker` keeps the four fields (`startDate`, `startTime`, `endDate`, `endTime`) in local state, seeded from the parent's stored range values. Editing a date or time updates only these drafts, so the displayed range does not change yet.
- **Apply**: the button is disabled while any draft is invalid. Clicking it calls `onApply` with all four values and closes the menu; the parent stores the values and the displayed range updates.
- **Cancel**: closes the menu without applying the drafts; reopening the editor starts again from the parent's stored range values.

Choosing **Custom Period** opens the editor in place without closing the menu.

Outside interaction is configured at two levels:

- Each `DatePicker` uses `closeOnSelect={true}`, so picking a date closes that calendar immediately and leaves the custom editor open.
- The parent `Menu` turns `closeOnInteractOutside` off while the custom editor is visible and back on once it is hidden. While the editor is visible, clicking elsewhere does not dismiss the menu; once it is hidden, an outside click closes the menu as usual.

## Props

### DatePicker

| Name | Type | Default | Description |
| :--- | :--- | :------ | :---------- |
| closeOnSelect | boolean | false | Determines if the date picker should close automatically after a date is selected. |
| defaultValue | Date \| string | | The default selected date. If the `defaultValue` is a string, it will be parsed to a `Date` object in accordance with the `inputFormat`. |
| defaultIsOpen | boolean | false | Whether the date picker is open by default. |
| firstDayOfWeek | number | 0 | The first day of the week.<br/>0 = Sunday<br/>1 = Monday<br/>2 = Tuesday<br/>3 = Wednesday<br/>4 = Thursday<br/>5 = Friday<br/>6 = Saturday |
| formatDate | function | | A callback called to return the formatted date string in the given format.<br/><br/><b>Signature</b><br/>`function(date, format, options) => void`<br/>_date_: The original date.<br/>_format_: The string of [format tokens](https://www.unicode.org/reports/tr35/tr35-dates.html#Date_Field_Symbol_Table).<br/>_options_: An object with options. |
| inputFormat | string | 'yyyy-MM-dd' | The default date format is ISO 8601 (`yyyy-MM-dd`). You can change the input format in accordance with the locale. The input value will be parsed to a `Date` object with `dd` as day, `MM` as month, and `yyyy` as year. |
| isOpen | boolean | | If `true`, the date picker will be open. |
| offset | [skidding, distance] | [0, 0] | The skidding and distance of the date picker. |
| minDate | Date | | The minimum date that can be selected. |
| maxDate | Date | | The maximum date that can be selected. |
| onChange | function | | A callback called when the value (the selected date) changes.<br/><br/><b>Signature:</b><br/>`function(value) => void`<br/>_value_: The selected date. |
| onClose | function | | Called when closing is requested, including clicks outside the input and calendar panel, Escape, and date selection when `closeOnSelect` is `true`. In controlled mode, update `isOpen` to close the popup. |
| onError | function | | An error-first callback called when the date validation returns an error (or the date is valid after error).<br/><br/><b>Signature</b><br/>`function(error, value) => void`<br/>_error_: The error message. It will be `undefined` if the date is valid after error.<br/>_value_: The selected date. |
| onOpen | function | | Callback when the date picker is opened. |
| placement | string | 'bottom-start' | The placement of the date picker. One of: 'top', 'top-start', 'top-end', 'bottom', 'bottom-start', 'bottom-end' |
| portalled | boolean | false | If `true`, renders the date picker in a portal. |
| renderInput | function | | The `renderInput` prop allows you to customize the rendered input.<br/>The `props` argument of this render prop contains props of [InputControl](../../input-control) that you need to forward.<br/><br/><b>Signature:</b><br/>`function(props) => ReactNode`<br/>_props_: The props of the input.<br/>_returns (ReactNode)_: The node to render as the input. |
| shouldDisableDate | function | | Disable specific date.<br/><br/><b>Signature:</b><br/>`function(date) => boolean`<br/>_date_: The date to check.<br/>_returns (boolean)_: Return `true` if the date will be disabled. |
| value | Date \| string | | The selected date. If the `value` is a string, it will be parsed to a `Date` object in accordance with the `inputFormat`. |
